# 需求与决策记录（防断片）

> 这个仓库是**完全开源**的（MIT），本文件是项目的「上下文备份」。
> 对话断了、换模型了、隔几天回来、或者新人来共创，先看这份，再看 README。

## 一、用户原话要点（逐条落档）

1. 场景：AI 对话里每次都要手动加一段**固定提示词**，不加就「降智」、只凭上下文乱答。
2. 想要：点一下就能把预设提示词**贴进输入框**，不用在 App 之间复制粘贴。
3. 迭代过的取舍：
   - 不要 2022 年的停更项目，要 2025/2026 年还在更新的；
   - 链接要**一个代码框一条**，不要一堆链接堆一起；
   - 要中文友好；
   - **不要一堆多余功能**，只要「粘贴提示词」这一件事干好。
4. 最终定案：**不做输入法**。改成一个**悬浮窗 App**：
   - 平时是一个小悬浮球；
   - 点开展开成方形悬浮窗，上面**一排**预设提示词；
   - 点一条 → 文字进当前输入框；
   - **不跟输入法抢**，输入法保持不变；
   - 提示词的增 / 删 / 改 / 编辑在**软件主页面**里做；
   - 要有完整项目文件，防止对话断片丢上下文。
5. 后续追加：
   - 页面要**用代码画出来自己看一眼**，不合适的地方改掉，可视化层级做好；
   - **新建一个开源仓库**并把仓库页面维护好，欢迎共创；
   - 上游代码来源说清楚，该自己写的自己写、该指向上游的指向上游；
   - **LOGO 和名字自己设计**、UI 优化好；
   - 把包推到 Releases，给出可供下载工具订阅的链接。
6. 交付方式：先在沙盒写核心代码；打包交给 GitHub CI；用户提供了一个 GitHub token 用于建仓 / 发布。
7. 用户加的「系统提示」：用户想法不一定对，要有自主判断；说错要指出、不完善要纠正；
   **动手前把需要核实的点跟用户说清楚**；做软件要有项目文件防断片。

## 二、必须纠正 / 已向用户说明的事实

| 用户设想 | 实际情况 | 处理 |
|---|---|---|
| 「悬浮窗检测输入位置，直接往里写」 | 普通 App 拿不到别的 App 的 `InputConnection`，那是 IME 专属 | 改用 `AccessibilityService.findFocus(FOCUS_INPUT)` |
| 「不占输入法 = 不需要额外权限」 | 必须用户手动开一次无障碍；Android 10 起不能 adb 直接开、13 起有安全提示 | README 置顶说明，主页面做状态灯 + 一键跳设置 |
| 「悬浮窗别影响输入框」 | 浮窗若抢焦点，输入框失焦、`FOCUS_INPUT` 返回 null | 全部浮窗强制 `FLAG_NOT_FOCUSABLE` |
| 「给我一个 GitHub token 跑 CI」 | 编译 + 发 Release 用内置 `GITHUB_TOKEN` 就够；PAT 该放 Secrets，且已出现在聊天里、建议用完轮换 | 仓库与 CI 里不写任何凭据，见 SECURITY.md |
| 「releases 页面的订阅链接」 | Releases 页没有可直接订阅安装包的链接：下载工具订阅的是**仓库地址**（自己去抓 `.apk`），`.atom` 只是更新通知 | README 明确给三类链接并说明区别 |
| 「点一下就贴进去」 | 部分输入框拒绝 PASTE / SET_TEXT | 三级兜底：PASTE → SET_TEXT(按选区拼接) → 留剪贴板 + Toast |

## 三、技术决策

- **悬浮层**：`TYPE_ACCESSIBILITY_OVERLAY`（无障碍服务自绘），**不申请 `SYSTEM_ALERT_WINDOW`**，
  Manifest 零 `uses-permission`。比用户设想的还少一个权限。
- **插入链**：PASTE 优先（保光标、不覆盖半句草稿）→ SET_TEXT 兜底（按 `textSelectionStart/End`
  拼接，避免清空）→ 剪贴板兜底。成功插入后还原原剪贴板，失败时故意保留提示词供手动粘贴。
- **焦点定位**：`FOCUS_INPUT`，不用 `FOCUS_ACCESSIBILITY`；`node.recycle()` 必做。
- **数据层**：`SharedPreferences` + `org.json` 字符串，不用 Room/DataStore；条目少，零依赖最稳。
- **UI**：原生 `Activity` + View/XML，不用 Compose / AndroidX / Material 组件。
  理由：悬浮窗 + 无障碍已经够多系统交互，第三方依赖只会给 CI 增加失败面。
- **联动**：Main Activity 与 Service 同进程，用 `companion object instance` 直连
  `refreshFromSettings()`，不绕广播/aidl。每次展开面板重新 `repo.list()`，保证增删改即时生效。
- **版本**：minSdk 26 / targetSdk 34 / compileSdk 34，AGP 8.5.2 + Kotlin 1.9.24 + Gradle 8.7 + JDK 17。
- **CI**：`setup-java` → `setup-android` → `setup-gradle` → 生成 wrapper → `assembleDebug` →
  `upload-artifact` → 打 tag / 手动勾选时 `gh release create` 挂 `citie.apk`。
- **目录名**用英文 `prompt-float`，交付与文档用中文。

## 四、UI 自查（用代码画出来看过）

生成脚本思路见 `docs/preview/ui_review_v1.png` → `ui_review_v2.png`（Pillow + 文泉驿微米黑，
三屏并排：主页面 / 悬浮球收起 / 展开面板）。

**v1 发现并已改掉的问题：**

| 问题 | 改法 |
|---|---|
| 列表项 ↑↓编辑删除 四个按钮挤在标题行，标题被压窄、容易误触 | 收进 `⋯` 菜单（上移/下移/编辑/删除），标题 + 预览成为主视觉，改卡片式布局 |
| 顶部标题直接贴屏幕，没有品牌层级 | 加渐变品牌头（LOGO + 名称 + 副标题 + 版本） |
| 状态只有一行干巴巴开关，启用后按钮还写「去开启」 | 状态卡改主状态 + 解释行；启用后按钮降级为「管理无障碍设置」 |
| 面板死钉在球下方，球拖到下半屏会被键盘/屏幕边缘吃掉 | `computePanelY()` 按预估高度自动翻到球上方 |
| 展开后球和面板看不出从属关系 | 球变深蓝 + 白环激活态，面板加品牌竖条锚点 |
| 悬浮球可拖到最底部压住输入框 | `snapToEdge()` 里把 y 夹在 `screenH - 220dp` 以上 |
| 横向 chips 没有「可滑动」提示 | hint 改为「点一条即插入当前输入框 · 左右滑动看更多」 |
| 空列表时页面一片空白 | 加空状态引导卡 + 条数显示 |

**命名 / LOGO**：应用名由「提示词悬浮球」改为 **「词贴」**（英文 PromptFloat）；
LOGO 用 Pillow 自绘：蓝色渐变圆角方块 + 白色「词」+ 右下角贴入箭头/光标，
输出 `res/drawable/ic_launcher.png` 与 `docs/preview/logo.png`。**没有用任何现成图标素材。**
