# 项目文件（不是软件源代码）

这个目录放的是**项目管理资料**，和 `app/` 下的软件源代码不是一回事。
按约定放在**同一个仓库**里，方便一起版本化、一起追溯，但边界要清楚：

| 路径 | 是什么 | 谁改 |
|---|---|---|
| `app/` | Android 源码：Kotlin、XML、资源、`debug.keystore`，编译出 APK | 改功能时 |
| `.github/` | CI 工作流、issue 模板 | 改构建/协作流程时 |
| `docs/preview/` | 用代码画出来的 UI 预览图与 LOGO | 改界面后 |
| `project/` ← 这里 | 需求原话、决策记录、版本与发布约定、开发者日志规范、待办 | 改需求/排 bug 流程时 |
| `README.md` / `CREDITS.md` / `CONTRIBUTING.md` / `SECURITY.md` / `LICENSE` / `CHANGELOG.md` | 仓库门面与协作规则 | 对外说明 |

**一句话**：改代码动 `app/`，改「我们为什么这么做」动 `project/`。
两者都在 `zjh1934/prompt-float` 这一个仓库里，不另开仓库、不放 wiki（wiki 不容易跟着 tag 走）。

## 目录索引

- [需求与决策.md](需求与决策.md) —— 需求原话逐条落档、被纠正的事实、技术决策、UI 自查记录。**防断片，先看这份。**
- [版本与发布.md](版本与发布.md) —— 包名 / 签名固定规则、每次出包的小版本约定、历次发布记录。
- [开发者日志说明.md](开发者日志说明.md) —— 日志记什么、不记什么、贴出来怎么定位问题。
- [待办与已知限制.md](待办与已知限制.md) —— 还没做、需要真机共创验证的部分。
