# 版本与发布约定

## 一、包名：永久固定，不许改

```
com.yuanbao.promptfloat
```

从 v0.1.0 起就是这个，**任何版本都不许改**。改 `applicationId` 会让 Android 把它当成一个新 App，
用户就必须卸载重装，而且悬浮球/无障碍授权、提示词数据全都留不下来。

> ⚠️ 纠正一个常见误判：**「每次安装都要卸载」不是包名变了。**
> 真正原因是签名。GitHub Actions 每次都是全新 runner，默认 `~/.android/debug.keystore`
> 会随机重新生成 → 同一个包名的 APK 签名不同 → Android 拒绝覆盖安装 → 只能先卸载。
> v0.1.1 已修：见下一节。

## 二、签名：也固定下来

`app/debug.keystore` 是一把**公开的开发签名**（alias `androiddebugkey`，密码 `android`），
随仓库一起提交。所有构建（本机 / CI / 任何 fork 的 CI）都用同一把钥匙。

> ⚠️ **一次性代价，必须说清楚**：`v0.1.0` 是在加固定签名**之前**由 CI 发布的，
> 用的是那台 runner 临时生成的随机 debug 密钥（runner 已销毁，密钥拿不回来）。
> 所以 **`v0.1.0 → v0.1.1` 这一跳仍然要卸载一次**，没法补救。
> **从 `v0.1.1` 起往后的所有版本**都用同一把固定签名，永久免卸载。
> 如果你还没装过 v0.1.0，直接装 v0.1.1 就行，不存在这个问题。

- `app/build.gradle.kts` 里 `signingConfigs.getByName("debug")` 指向它，debug 与 release 两种构建都用它。
- CI 的「校验签名」步骤会打印 APK 证书 SHA-256，可用来核对不同版本是否同一把签名。
- **它不是发布私钥，不提供任何安全保证**，任何人都能用仓库里这把钥匙签名。
  正式上架渠道应另配私有 release 签名（放 Secrets，绝不入库）。详见 `SECURITY.md`。
- v0.1.1 证书 SHA-256：
  `73:AF:3F:C4:F7:66:3F:DB:8A:3D:50:AD:75:E8:F2:8A:9A:8F:E6:4C:43:F8:AC:28:C7:43:B2:ED:00:D8:58:32`

## 三、每次出包都升一个小版本

约定（已写进 `.github/workflows/build.yml`）：

1. `app/build.gradle.kts`：`versionName` 的 **patch 位 +1**（`0.1.0 → 0.1.1 → 0.1.2 …`），
   `versionCode` 同步 **+1**。
2. 打同名 tag：`v${versionName}`，推送后自动触发 CI 发布 Release。
3. **唯一版本源是 `versionName`**。workflow 用 `sed` 读它，不再硬编码版本号。
4. **安装包命名 = 软件名(拉丁化) + v版本号 + `.apk`**，即 `Citie-v${versionName}.apk`
   （例如 `Citie-v0.1.2.apk`）。CI 用 `versionName` 动态拼名，不会出现 `app-debug.apk` /
   `citie.apk` 这种下载目录里一堆同名分不清谁是谁的文件。
   > 平台限制：试过 `词贴-v0.1.2.apk`，**GitHub Release 的 asset 文件名不支持中文**，
   > 上传时非 ASCII 被吞掉只剩 `-v0.1.2.apk`。故文件名用 ASCII 的 `Citie`，
   > 中文「词贴 v0.1.2 安装包」放在 asset 的 `label` 字段（实测 label 支持中文）。
5. `CHANGELOG.md` 补一条，`project/版本与发布.md` 补一行发布记录。

## 三之二、订阅地址（两类工具别填错）

| 工具类型 | 填什么 |
|---|---|
| RSS 2.0 / Atom / JSON Feed 订阅框 | `https://github.com/zjh1934/prompt-float/releases.atom` |
| Obtainium 等自动抓包安装 | `https://github.com/zjh1934/prompt-float` |

> GitHub 原生 `releases.atom` **只有版本通知，不带 APK 附件**（无 `<enclosure>`）。
> 订阅后能收到「出新版本了」，但仍要自己去 Releases 下包。
> 之前写「下载工具订阅仓库地址」只对第二类工具成立，对 RSS 订阅框是错的 —— 已纠正。

只有修 bug / 小功能就升 patch；真有 Breaking Change（比如换包名，理论上不该发生）才动 minor。
